# results index

Each file is generated by the corresponding script; `peg_gr_001` and `peg_gr_002` are not two versions, but the results of the same evaluation protocol on two index instances.

| File | Generation command | Contents | Notes |
|---|---|---|---|
| `peg_gr_001.json` | `evaluate` (update instance) | Five-arm retrieval, visibility probes, cost | Main run; the host arm's vector table is incomplete on this instance |
| `peg_gr_002.json` | `evaluate --update-root artifacts/runs/edit` | Same as above, with the host arm switched to an instance with a complete vector table | The host numbers in paper 5.7 come from this file |
| `stability_3fold.json` | `evaluate_stability` | 3 folds, 120 questions | Requires the stability index |
| `ablation.json` | `ablation` | Three channel variants | Reuses existing host rankings |
| `baselines.json` | `baselines` | BM25, paragraph vector, text-unit vector, basic search | Includes timestamp feasibility conclusions |
| `controls.json` | `controls --paragraph-results results/peg_gr_002.json` | Three bypasses, multi-hop coverage, bootstrap intervals | Zero generation calls |
| `reindex.json` | `reindex_control` | Re-ingestion under new titles (control group B) | Requires the rename index |
| `generation.json` | `generation` | Three-arm answer EM/F1 and probes | About 140 generation calls |
| `local_effects.json` | `local_effects` | Neighborhood Jaccard, deletion side effects, scale latency | Zero generation calls |
| `rebuild_variance.json` | `index_variance` | Extraction density and host metrics across three rebuilds | Requires 3 rebuild instances |
| `integration.json` | `integration_cost` | Read host document table and build a PEG state | Zero generation calls |

Convention: cross-arm comparisons involving host retrieval must be completed within the same run; generation metrics fluctuate by ±1 question (paper limitation 11).
